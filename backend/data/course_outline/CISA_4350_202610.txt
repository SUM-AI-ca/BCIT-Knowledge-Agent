### Course Description
​​This course introduces and provides opportunities for students to build a variety of Cloud infrastructures, services and security employed by small to medium size businesses through a guided, hands-on approach. Students learn how to design systems that are secure, reliable, high-performing, and cost efficient. Students will configure, implement, test, troubleshoot, optimize, and document mainstream Cloud services. Topics include networks, storage, database, analytics, security, accounts, and automation as well as design for high availability, fault tolerance, and scalability to meet current industry benchmarks. The content of this course is supported by the AWS (Amazon Web Services) Learning Academy.
### Course Learning Outcomes/Competencies
Upon successful completion of this course, the student will be able to:
- Describe Private, Public, community and hybrid Cloud computing Frameworks
- Create and manage virtual networks across multiple physical nodes
- Implement cloud storage allowing volumes to be created locally or served remotely
- Manage compute, network, and storage resources in the data center and allocate those resources to users using mainstream Cloud platforms
- Describe enterprise Cloud computing building blocks
- Install and configure Cloud software, tools & Services
- Design systems that are scalable, fault tolerant and have high reliability
- Describe the skill set required to meet business needs with modern Cloud computing and challenges associated with the adoption of the Cloud.
- Deploy Cloud management, analytic and monitoring services
- Describe how to leverage the capabilities of the Cloud to support automation
- Create, manage, and provision load balancing, auto scaling and serverless applications
### Learning Resources
Core learning resources used throughout the term:
- AWS Academy: Cloud Architecting (Architecture) modules (graded progress component).
- AWS Skill Builder (optional practice): Labs, digital courses, and exam-style questions.
- AWS Documentation (official service guides): VPC, EC2, S3, IAM, CloudWatch, ELB/ASG, Lambda, CloudTrail, etc.
- Instructor-prepared lecture slides (PDF) and lab manuals (student + instructor versions).
- Brightspace/D2L: quizzes, announcements, submission dropboxes, and gradebook feedback.
- AWS Console, AWS CloudShell, and AWS CLI v2.
Note: AWS Academy content is used as a structured baseline, while course labs emphasize verifiable evidence, troubleshooting, and architecture-level decisions suitable for workplace readiness.
### Course Goals
By the end of the course, students will be able to design and deploy secure, scalable, and observable AWS solutions; troubleshoot common failures using evidence-driven methods; and justify design decisions using basic architecture decision records (ADR).

### Course Specific Requirements
Accounts and Cost Control
Students will use an individual AWS account (Free Tier where available) for course labs that occur outside the AWS Academy environment. AWS account creation typically requires a valid payment method (e.g., credit card) for identity verification. Labs are designed to minimize cost; however, students are responsible for any charges incurred on their personal AWS account and must follow required cost-control and teardown steps. Students who are unable to create an AWS account must notify the instructor by the end of Week 1 to arrange an equivalency pathway (e.g., AWS Academy environment and/or supervised in‑class demonstrations/lab tests) that assesses the same learning outcomes.
Standard Lab Region
- All course labs use AWS region us-west-2 (Oregon) unless explicitly stated otherwise.
Required Tools
- AWS Console, AWS CloudShell, and AWS CLI v2. Students must be able to capture command outputs into the provided outputs.txt template.
### Other information
AWS Accounts, Free Tier, and Billing Responsibility: Students will use an individual AWS account (AWS Free Tier where applicable). Creating an AWS account typically requires a valid payment method for identity/billing verification. Students are responsible for any charges incurred due to misconfiguration, selecting non–Free Tier resources, or failure to shut down resources. The course provides teardown guidance and verification requirements to minimize billing risk.
Alternative Pathway (If a Student Cannot Create an AWS Account): Students who cannot create an AWS account must notify the instructor by the end of Week 1. An equivalency pathway may be provided to assess the same learning outcomes with a comparable workload and evaluation criteria (e.g., supervised in-lab verification using instructor-provided sandbox/demo evidence plus a scenario-based assessment). The goal is equity without lowering standards.
AWS Academy (Cloud Architecting) – Self-Paced Learning and Instructor Role: AWS Academy Cloud Architecting is a structured, self-paced learning system that includes graded activities (videos, quizzes, labs, and checks). The instructor acts as a facilitator by clarifying concepts, linking Academy content to course outcomes, and supporting in-class learning activities. To maintain fairness, the instructor will not troubleshoot or complete individual students’ graded AWS Academy tasks in a way that gives some students an advantage over others. Students are responsible for completing AWS Academy work independently.
AWS Academy Progress Checkpoints (ungaraded) : Checkpoint items in the schedule refer to AWS Academy progress/completion expectations for a specified module range (posted in Brightspace/D2L). Checkpoints help students stay on track and support timely completion before the course completion deadline.
Use of AI Tools and Academic Integrity: AI tools (e.g., ChatGPT, Copilot, vendor assistants) may be used for learning support (concept clarification, studying, syntax reminders). However, all submitted work must be the student’s own and students remain responsible for correctness. Supervised Lab Tests: AI tools are not permitted during supervised lab tests unless explicitly authorized by the instructor for the entire class. Lab Activities/Submissions: AI tools may be used only as an aid; students must produce verifiable evidence and be able to explain steps and reproduce a verification action if requested. The instructor may use automated/manual integrity checks (e.g., validation of required outputs, timestamps, identity proof, and similarity indicators). If concerns arise, students may be asked to complete a short in-class verification.
Late Submissions
Lab Activity submissions (outputs.txt only) are due by the start of the next scheduled class (08:30 AM). Late submissions are accepted for up to 3 calendar days after the due time with a penalty of 10% per day (or part of a day). After 3 days, submissions are not accepted unless approved accommodation and documentation applies.
Academic Integrity and Evidence Standards
Lab grades require verifiable evidence of the student’s own work. For this course, the required evidence artifact is a single outputs.txt file generated using the course template and populated with real AWS CLI/CloudShell command outputs (including resource IDs, ARNs, and state/verification results). Submissions that are incomplete, lack proof tokens, or are substantially similar to others may be flagged for review and may require an in-lab live demonstration.

### Course topics
- AWS global infrastructure, accounts, IAM, and security fundamentals
- VPC networking: subnets, routing, security groups, NACLs, gateways, connectivity basics
- Compute and storage: EC2, AMIs, EBS, S3, backups and lifecycle management
- High availability and scalability: ALB, target groups, health checks, Auto Scaling
- Database concepts and connectivity: RDS basics
- Observability and operations: CloudWatch logs/metrics/alarms; troubleshooting workflow
- Serverless and integration: Lambda, SQS/SNS (fundamentals)
- Architecture design: cost, performance, reliability, security, operational excellence; Well-Architected alignment
- Advanced networking overview: VPC peering and Transit Gateway (concepts + constrained lab evidence)
