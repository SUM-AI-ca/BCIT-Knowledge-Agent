## Course Description
This course covers software and hardware design for real-time embedded systems. Topics include real-time implementation of DSP algorithms, code and hardware optimization for speed and power, real-time operating systems, reliable operation, and overall system architecture. In the laboratory, students will apply selected concepts learned in the lectures by implementing them on a development board centered around a DSP-oriented microcontroller. This course uses C as the programming language. There is some interaction with assembly code. Tutorial time early in the course is available to bring students back up to speed on selected topics such as C programming.

## Course Learning Outcomes/Competencies
Upon successful completion of this course, the student will be able to:

- Select a processor or other implementation platform for the real-time embedded task at hand.
- Design and implement hardware interfaces, including the related software.
- Understand real-time operating system concepts including scheduling, interrupt handling, context switching, task synchronization, and resource sharing.
- Predict and measure real-time performance.
- Consider all aspects, including software and hardware, and technical and non-technical concepts, in the design of real-time embedded systems.

## Course Goals
These goals are tentative but ambitious; their coverage may vary depending on time, level of participation, and enthusiasm of the students. Subject to some changes in mutual agreement with the participants and their interest in the subject.

Upon successful completion, the student will be able to:

Embedded Systems Architecture

- Understand the differences between general-purpose computers and embedded systems
- Differentiate various programmable computational devices: CPU, GPU, DSP, MCU, MPU, etc.
- Determine the requirements of hardware components and software development platforms needed by various types of projects
- Understand the embedded system architecture role in the design of a successful product
- Learn testing and debugging methods, and tools required by embedded system development

Real-Time Programming

- Understanding the concept of time in programming and other related activities
- Think of programming as a combination of algorithms and time that allow the system to respond in a timely fashion
- Understand the impact of the programming language artifacts that interact with time even in indirect but meaningful ways
- Learn about hardware features and particularities in handling time (interrupts, timers, latencies, jitter, synchronization, events)
- Explore various means to achieve real-time behavior in embedded systems programming (ISRs, foreground/background method, real-time frameworks, state machines, RTOS, etc.)
- Design modular device drivers that can be easily instantiated for multiple processing threads
- Integrate properly existent RTOS or real-time frameworks and libraries into the application
- Understand and use correctly the context switching and task scheduling methods
- Demonstrate inter-task communication patterns (shared memory concept, messages, queues, mailboxes) and their use
- Understand concurrency issues and the inter-task synchronization methods
- Learn various algorithms of priority-based scheduling
- Determine the memory requirements regarding size and management during the life of the application/product; implement a dynamic memory allocation algorithm
- Learn to apply standard methods for fault handling in autonomous systems (fault detection and isolation, fault tolerance, fault recovery, constraint handling, performance optimization, etc.)
- Understand the implications of data type choices for a given system and MCU capabilities; methods for mitigating performance issues (e.g. by using alternative data representation)

Embedded Real-Time Applications (at least two, time permitting)

- Understand GPIO and play with LEDs; using GPIO as test points for a scope or logic analyzer
- Measure the frequency of a digital signal with a timer using its capture feature and interrupts
- Using UART to communicate with a PC for debugging, monitoring, etc.
- Learn how ADC and DAC connect the system with the analog world; demonstrate a simple signal acquisition application that measures the average value and noise level of the input
- Learn what is a data acquisition and generation system, and its use; demonstrate simple digital filtering of the ADC input signal and streaming the result to the DAC (audio domain)
- Using PWM to control a DC motor in several ways: open loop, closed loop with PID
- Using a watchdog to detect application fatal errors and unrecoverable hardware faults

Writing Code for Safety-Critical Devices (intended but limited by time)

- Learn about safety levels and their impact
- Platform choice impacts safety too: learn how to pick the right platform
- Methods to reduce coding errors (changing the mindset, using safe libraries, assertive debugging, code by contract, static analysis, thinking of the unthinkable, etc.)
- Run-time debugging (intrusive and non-intrusive methods, hardware for debugging, etc.)
- Coding standards for Safety-Critical Systems (e.g. MISRA C for transportation)

## Course Specific Requirements
While no prerequisite courses are indicated, some previous knowledge of the following is welcome:

- Basic lab equipment operation (multimeter, oscilloscope, power supplies)
- Number systems, number representation, conversions between number systems, Boolean algebra, binary operations
- Digital circuits and techniques and terminology, combinational and sequential logic, state diagrams
- C programming language (beginner to intermediate level is a good starting point, advanced level is recommended)
- Previous exposure to microcontrollers and microprocessors (it can be at the DIY or Maker level)
- Basic algorithms and data structures (lookup, hashing, lists, stacks, queues, trees, etc.)

Most of the mentioned knowledge will help to achieve more in class and laboratory and use the tutorials for getting help with the assignments, projects, and the final exam. Student cooperation in preparing for this course is strongly encouraged. Please review the references, ask for guidance in the first week, and get advice from the instructor.
